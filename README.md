# mess

Лёгкая голосовалка для своих. Голос, чат, картинки — без полутора гигабайт
оперативки на встроенный Chromium.

- **Десктоп-клиент** (Linux / macOS / Windows): Go + Fyne + Pion + Opus.
  Нативный, ~100–150 МБ RAM в звонке. Качается с GitHub Releases. Сервер
  зашит в клиент намертво (`discord.djaploy.dev`), в UI поля «сервер» нет —
  вход строго через Discord, кнопкой.
- **Сервер**: один Go-бинарь без базы данных. SFU на Pion — сервер только
  пересылает RTP-пакеты, транскодинга нет, CPU почти не ест. HTTPS получает
  сам через Let's Encrypt.
- **Веб-страница**: визитка со ссылкой на релизы плюс страницы приглашений
  (`/i/<код>`). Полноценного веб-клиента больше нет — общение только в
  приложении.

Сессия живёт полгода: при каждом запуске клиент тихо продлевает её через
`/api/refresh`, повторный вход нужен только после полугода полного простоя.

## Как устроено для юзера

Группы — как «серверы» в Discord. Внутри группы текстовые и голосовые каналы.
Друзей зовёшь ссылкой-приглашением (правый клик по группе → «скопировать
ссылку-приглашение»), они вставляют её в «+» → «войти по коду».

Видно: кто в сети, кто сидит в каком голосовом канале (прямо в списке каналов,
не заходя внутрь), кто говорит, кто в муте. При подключении к голосовому —
зелёная панель с названием канала, временем в нём и задержкой.

В чате: ответы на сообщения (кнопка появляется при наведении), удаление своих
сообщений, картинки открываются во весь экран прямо в окне. В настройках звука —
выбор микрофона и наушников плюс ползунок чувствительности (шумодав). Громкость
конкретного человека крутится правым кликом по нему в голосовом канале.

## Быстрый старт (локально)

```bash
go run ./cmd/backmess          # сервер на http://localhost:8080
```

В `.env` нужны `DISCORD_CLIENT_ID` и `DISCORD_CLIENT_SECRET` (см. «Discord
OAuth» ниже) — гостевой вход выключен по умолчанию (`ALLOW_GUESTS=false`),
как и в проде.

Десктоп-клиент (нужны `libopus` и `pkg-config`, см. «Сборка клиента»).
Сервер в клиенте зашит на `https://discord.djaploy.dev` — для локального
теста подменяется переменной окружения `MESS_SERVER`:

```bash
MESS_SERVER=http://localhost:8080 go run -tags nolibopusfile ./cmd/backmess-app
```

## Деплой сервера

Два режима — выбираются наличием `DOMAIN` в `.env`.

**Режим A — сервер один на машине, порты 80/443 свободны.** mess сам
получает сертификат Let's Encrypt и слушает 80/443 напрямую:

```bash
# .env:
DOMAIN=discord.djaploy.dev
PUBLIC_IP=<публичный IP сервера>
DISCORD_CLIENT_ID=...
DISCORD_CLIENT_SECRET=...

docker compose up -d --build
```

**Режим B — на машине уже есть nginx/caddy (как у нас с djaploy) —
`DOMAIN` не трогаем, чтобы mess не полез на 80/443 сам.** mess слушает
только внутренний порт, TLS терминирует существующий прокси:

```bash
# .env:
ADDR=:8091                              # свободный внутренний порт
BASE_URL=https://discord.djaploy.dev    # для OAuth-редиректов и cookie Secure
PUBLIC_IP=<публичный IP сервера>        # только для WebRTC, к веб-портам не относится
DISCORD_CLIENT_ID=...
DISCORD_CLIENT_SECRET=...

docker compose up -d --build
```

и в существующем nginx/caddy добавить виртуальный хост
`discord.djaploy.dev`, проксирующий на `127.0.0.1:8091` (включая
`/ws` — не забыть `Upgrade`/`Connection` заголовки для вебсокета).
Порты 80/443 и другие сайты (сам djaploy) остаются как есть, не трогаются.

### Как это развёрнуто сейчас (discord.djaploy.dev)

Режим Б, рядом с проектом djaploy на том же сервере:

- mess — systemd-сервис `mess`, бинарь `/home/dj/mess/mess-server`, конфиг
  `/home/dj/mess/.env`, данные `/home/dj/mess/data`.
- Слушает `172.18.0.1:8091` — это адрес docker-моста, то есть снаружи порт
  недоступен, достучаться может только Caddy. Публично торчит лишь медиа-порт
  8443, которому это и положено.
- TLS и маршрутизацию делает Caddy из djaploy: в его `Caddyfile` добавлен блок
  `discord.djaploy.dev` с `reverse_proxy 172.18.0.1:8091`. Порты 80/443 и сам
  djaploy не тронуты.

Обновить сервер после изменений в коде:

```bash
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -ldflags="-s -w" -o mess-server ./cmd/backmess
scp mess-server dj@144.31.168.88:/home/dj/mess/mess-server.new
ssh dj@144.31.168.88 'mv /home/dj/mess/mess-server.new /home/dj/mess/mess-server \
  && chmod +x /home/dj/mess/mess-server && sudo systemctl restart mess'
```

Посмотреть логи: `ssh dj@144.31.168.88 'journalctl -u mess -f'`.

В обоих режимах отдельно, напрямую в интернет (WebRTC не проксируется):
**MEDIA_PORT (по умолчанию 8443) UDP+TCP** — открыть в файрволе. TURN не
нужен: сервер сам является медиа-узлом с публичным IP. Важно, чтобы этот
порт не совпадал с чем-то, что уже занято на сервере (у djaploy проверить).

Все переменные окружения — в `internal/config/config.go` (ADDR, DOMAIN,
BASE_URL, PUBLIC_IP, MEDIA_PORT, DATA_DIR, ALLOW_GUESTS, MAX_UPLOAD_MB,
SESSION_SECRET).

### Discord OAuth

В [Discord Developer Portal](https://discord.com/developers/applications) →
OAuth2 → Redirects добавь **оба**:

- `http://localhost:8080/oauth/callback` — для локальной разработки
- `https://discord.djaploy.dev/oauth/callback` — для прода

Секреты держи только в `.env` (он в .gitignore). Если секрет успел
засветиться где-то ещё — перегенерируй его в портале.

## Сборка клиента

Зависимости: компилятор C (cgo), `libopus`, `pkg-config`.

- **macOS**: `brew install opus pkgconf`
- **Debian/Ubuntu**: `sudo apt install libopus-dev pkg-config libgl1-mesa-dev xorg-dev libxkbcommon-dev`
- **Windows**: MSYS2 → `pacman -S mingw-w64-x86_64-gcc mingw-w64-x86_64-opus mingw-w64-x86_64-pkg-config`

```bash
make app   # или: go build -tags nolibopusfile ./cmd/backmess-app
```

Готовые сборки под три ОС собирает GitHub Actions по тегу `vX.Y.Z`
(`.github/workflows/release.yml`).

### Как друзьям это запустить

В релизе три файла — по одному на систему.

- **Windows** — `mess.exe`: один файл, просто скачать и запустить. Никаких
  dll рядом класть не надо, всё вшито внутрь.
- **macOS** — `mess-macos.dmg`: открыть, перетащить mess в Applications.
  Один файл на любой мак: внутри универсальный бинарь (Apple Silicon + Intel).
  При первом запуске система ругнётся, что приложение от неизвестного
  разработчика — надо **правой кнопкой по mess → «Открыть»**, и подтвердить.
  Через обычный двойной клик не пустит. Если система совсем упирается:
  ```bash
  xattr -dr com.apple.quarantine /Applications/mess.app
  ```
- **Linux** — `mess-linux-amd64.tar.gz`: распаковать, запустить `./mess`,
  либо `./install.sh` — тогда появится в меню приложений с иконкой.

Подписи и нотаризации нет (это $99/год Apple Developer), поэтому на маке
разовый ручной шаг обязателен. Приложение подписано ad-hoc — этого хватает,
чтобы оно вообще запускалось на Apple Silicon, но Gatekeeper всё равно
попросит подтверждение.

Собрать пакеты локально можно теми же скриптами, что использует CI:

```bash
./scripts/package-macos.sh 0.1.0 mess-macos.dmg
./scripts/package-linux.sh 0.1.0 mess-linux-amd64.tar.gz
```

Пока рекомендуются **наушники**: программного эхоподавления в нативном
клиенте ещё нет.

## Как это устроено

```
клиент ──gw───> сервер: presence, дерево групп/каналов, текстовый чат
клиент ──ws───> сервер: сигналинг голоса (join/offer/answer/candidate)
клиент ──rtp──> сервер ──rtp──> остальные   (SFU, один порт 8443 udp+tcp)
```

- Два вебсокета: постоянный `/gw` (живёт, пока открыто приложение) и `/ws`,
  который поднимается только на время звонка. Поэтому онлайн-статусы и новые
  каналы появляются мгновенно, без опроса сервера.
- Состояние (группы, каналы, участники, история чата) — в `data/state.json`,
  запись отложенная и атомарная. Базы данных нет.

- Одна SFU-комната = один голосовой канал; комната живёт, только пока в ней
  кто-то есть.
- У каждого участника один PeerConnection и три фиксированных слота треков:
  микрофон / камера / экран. Слоты включаются через `replaceTrack` без
  ре-негосиации; offer шлёт только сервер → glare невозможен.
- Стримы именуются `<user id>:<mic|cam|screen>` — по имени сразу понятно, чей
  это звук, поэтому индикатор «говорит» вешается на нужного участника.
- Картинки в чате сервер жмёт до 1600px JPEG (гифки не трогает), отдаёт из
  `data/uploads`. История — последние 300 сообщений на канал.
- Аккаунтов нет: сессия — подписанная HMAC cookie на полгода, юзер приходит из
  Discord (гостевой вход есть в коде, но по умолчанию выключен —
  `ALLOW_GUESTS=false`).
